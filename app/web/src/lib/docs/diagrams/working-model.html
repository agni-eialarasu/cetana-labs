Rule

Kiro-native (reads committed .kiro/ → skills are real /commands). Emergency continuity, not a parallel operator lane — an operator stint here loses KiroCrew's persistent memory.

Three tiers. KiroCrew = Primary Operator (decides & governs, stateful) → Antigravity = Primary Executor (builds & verifies, executor-only — never operates, because it is stateless) → the merge gate is always yours. Kiro Web / IDE = Secondary (break-glass): Kiro-native, so each can stand in for either role — but only when KiroCrew is unavailable, as emergency continuity, never routine. Operator authority stays concentrated where the memory + governance live; executor throughput scales out on Antigravity. More executors = more throughput, never more operator or merge authority. Each surface uses a separate clone, sync via origin. Project metadata is app-CRUD (admin/projects) → just export-live-data → committed data/ (RFC-016 Phase 3).
