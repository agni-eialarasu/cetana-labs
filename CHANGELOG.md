## [0.13.0] - 2026-10-07
### Sprint 11: Process-Hardening & Multi-Executor Convergence (carry-forward of the planned product goal) — `v0.13.0`
> **Sprint note (honest record):** SPRINT-11's *planned* goal was the first post-MVP product features (`BK-012` app-level settings → `BK-013` branding, + the `BK-015` AI-assistant RFC). The sprint instead **pivoted into process/DX hardening + the multi-executor model** — work that de-risks and accelerates those product builds. The planned product items (`TSK-057` Ready, `TSK-060`/`TSK-061` Backlog) **carry forward to SPRINT-12**. What actually shipped:

Never force-pushes / `--all` / `--mirror` / bare push; preserves hooks; inherits `/commit-changes` secret-hygiene. `/commit-changes` unchanged (compose, don't rewrite). Authored on the Operator, built via `/spec-run` on the Kiro IDE Executor, human-verified (PASS), gated via `/review-pr`. `AGENTS.md §4` + the Working Model diagram updated in lockstep.

### Fixed
- **BK-018 fixed — redirect OAuth + PocketBase un-pinned to 0.40 (`BK-018`, `TSK-058`)**: Fixed the BK-018 root cause. GitHub sign-in now uses the **redirect-based `authWithOAuth2Code`** manual code-exchange flow (`listAuthMethods()` → persist PKCE `codeVerifier` + CSRF `state` in `sessionStorage` → redirect to GitHub → new `/oauth/callback` route verifies `state` and exchanges the code) instead of the all-in-one **popup** (`authWithOAuth2`), so it **never opens `/api/realtime`** — the SSE channel Railway's edge proxy breaks on PB 0.40 (spike-confirmed, Journal Entry 011 / `RFC-LAB-000-011` §4.5). The `Containerfile` pin moved **`0.28.4 → 0.40.4`** (workaround comment replaced with the redirect-flow rationale). M2→M4 preserved (`github_handle` linking, owner-write, RBAC, `(member)` guard, sign-out, persistence). Verified end-to-end **V1–V8 on a throwaway 0.40 Railway** instance via the `RFC-LAB-000-012` CLI + `verify-bundle` flow (bundle proven wired to throwaway, prod absent, before any live test — the anti-false-negative discipline). **Live prod stayed 0.28.4 throughout** — the live version cutover is the separate **`BK-019`** promotion. Delivered via the AIDLC lifecycle (redirect flow is also PocketBase's recommended production OAuth). [PR #46]
- **`status.json` date-drift — recurring CI failures eliminated (`BK-020`)**: The status-sync check failed on ~5 unrelated PRs because `days_ago` (and the date-derived `is_stale`) were **stored** in `data/status.json` yet recomputed from *today* on every `--check`, so the committed file went "stale" purely as the calendar advanced. Fixed by **not storing the time-relative fields** (`last_updated` is the source of truth) and **deriving `days_ago`/`is_stale` at read-time in the SPA** (`data.ts`) — proven date-independent at a +400-day mocked clock. Also makes the displayed "days ago" always current. [PR #43]
- **Backend CI deploy fixed — Railway Root-Directory doubling (`BK-022`, ops follow-up to `BK-021`)**: The `deploy-backend.yml` workflow deployed from `working-directory: app/pocketbase` with `--path-as-root .` while the Railway service Root Directory was also `app/pocketbase` → Railway looked for `app/pocketbase/app/pocketbase` → *"Root directory not found in the deployed source"* (build failed on the first backend merge). Fixed by deploying from the **repo root** (the combination proven on the throwaway); Railway's Root Directory scopes in and reads `app/pocketbase/railway.json`. CLI auth was never the issue. The prior red deploy **proved V4 live** (an ops alert that did not revert the merge — `done`=the merge, D50); the fix merge then **proved V1 live** (`Deploy complete` on `cetana-labs`). [PR #49]
